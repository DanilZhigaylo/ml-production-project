# Архитектура процесса автоматического переобучения модели (ML Retraining Pipeline)

Ниже представлена схема процесса автоматического переобучения модели прогнозирования отказов УЭЦН — от срабатывания триггера до развертывания в продуктивной среде.

```mermaid
graph TD
    A[Триггер переобучения: Расписание / Дрейк данных / Падение качества] -->|Сигнал о запуске| B[Сбор и предобработка новых данных]
    B -->|Свежий датасет / Фичи| C[Обучение новой версии LightGBM]
    C -->|Артефакт обученной модели| D[Валидация и проверка качества: ROC-AUC / Recall]
    D -->|Проверка успешна?| E{Решение о публикации}
    E -->|Нет: Качество ниже текущей| F[Логирование ошибки / Уведомление Data Scientist]
    E -->|Да: Метрики выше порога| G[Регистрация версии в Model Registry]
    G -->|Зарегистрированная модель| H[Автоматический деплой / CI/CD]
    H -->|Новая модель в продакшене| I[Мониторинг работы в контуре ЦДНГ]
